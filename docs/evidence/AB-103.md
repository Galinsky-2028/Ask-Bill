# AB-103 Operational telemetry alerts and diagnostics (partial)

**Repository:** `Galinsky-2028/Ask-Bill`. **Base:** main after PR #109. Head SHA/PR/CI recorded in the PR.

## Scope implemented and paths
- `packages/telemetry/index.mjs`: bounded aggregate counters (fixed route class x status class, latency buckets, allowlisted event names), declarative `evaluateAlerts()` (error ratio, slow ratio, event count), constant-time bearer check.
- `apps/web/application/server.mjs` / `start.mjs`: passive request observer; `GET /health/metrics` gated by `ASK_BILL_METRICS_TOKEN` (404 when unset); readiness failures recorded.
- `infra/alerts/rules.json`: reader/API/publisher 5xx, reader latency, readiness, provider failure and quota rules.
- `docs/ops/APPLICATION_RUNTIME.md`: operator section.

## Privacy evidence
`tests/telemetry.test.mjs` asserts that a request with an ID and a private question in the query leaves no trace of either in the snapshot, unknown event names are rejected, and metrics are unavailable without the exact configured token.

## Tests
`node --test tests/telemetry.test.mjs` 5 pass; full suite, lint and check pass locally on Node 24.19.0.

## Not done (remaining AB-103 scope)
Alert **delivery** to a real channel, source-freshness/queue-age/retention-backlog diagnostics from the worker and database, graphics failure rates from browsers, and the staging fault-injection verification (provider outage, stale source, dead-letter job, quota ceiling) required by the acceptance criteria. Operational acceptance: not_run.

## Rollback
