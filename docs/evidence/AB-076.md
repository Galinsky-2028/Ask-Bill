# AB-076 Performance replay recorder and choreography tools

**Repository:** `Galinsky-2028/Ask-Bill`. Head/PR/CI in the PR. Candidate character only; no art unit claimed.

## Scope implemented and paths
- `packages/character/performance/recorder.mjs`: recorder (focus decisions with the exact anchor/stage/viewport geometry used, answer phases, clips, dock moves, stage state/backend, layout changes), order-independent SHA-256 `layoutHash`, allowlist redaction (`redactEvent`) and strict validation (rejects any non-allowlisted field), and deterministic `replayPerformance` that re-derives each pointing decision with the current resolver and rejects another version or layout (`REPLAY_VERSION_MISMATCH`, `REPLAY_LAYOUT_MISMATCH`).
- Stage and glue: the optional `recorder` hook; the dev-only `ASK_BILL_CHARACTER_RECORDER=true` adds a trace download button; resize re-hashes the layout.
- `tools/performance/inspect.mjs`: timeline viewer and replayer (exit codes 0/2/3/1).

## Acceptance mapping
- *Reproduce a movement defect from version, layout and cue metadata without raw conversation*: `tests/replay-recorder.test.mjs` (5 tests): fixed route recorded and replayed with 0 divergences, altered decision reported as a divergence, layout and version mismatches rejected explicitly, injected question/quote/transcript text never stored, tampered trace rejected, CLI exit codes.
- `tests/replay/test_recorded_route_browser.py` (CI browser job): real Chromium records a route on the reader page and downloads the trace. The CLI replays it with 0 divergences and rejects another layout (exit 3). The trace contains neither the typed question nor source text.
